# LocalMeta 插件 × Jellyfin 12.1.0 兼容性检查报告

检查时间：2026-10-05 17:20
检查对象：`Jellyfin.Plugin.LocalMeta 0.3.0.0`（TFM net9.0，引用 Jellyfin.Controller 10.11.6）
目标宿主：Jellyfin 12.1.0（`C:\Program Files\Jellyfin\Server\`）

---

## 一句话结论

**插件代码本身与 12.1.0 兼容，但它现在根本没被加载。**
真正的问题不是"不兼容"，而是 **12.1.0 换了数据目录**，插件留在旧目录里没跟过去。

---

## 三个风险点

### 风险 1（严重）：数据目录迁移，库是空的
新 `data\jellyfin.db` 只有 **548 KB**（全新空库），日志有 `System initialization detected. Seed data` + 数据库迁移 `ChangePrimaryVersionIdToGuid` / `AddPrimaryVersionIdIndex`。

旧库状态（都在旧目录，未损坏）：
- `C:\Jellyfin\Data\data\jellyfin.db` —— 49 MB
- `C:\Jellyfin\Data\metadata\People\` —— 583 个演员目录（A 阶段脚本的成果）
- `C:\Jellyfin\Data\data\jellyfin.db.bak_localmeta_20261005_133649` 等备份齐全

即：12.1.0 目前是"干净安装"状态，媒体库、演员资料、观看记录全部需要重建。**这个问题比插件问题严重得多。**

### 风险 2（中）：TFM 不匹配
- 插件：`net9.0`
- 12.1.0 宿主 runtimeconfig：要求 `Microsoft.NETCore.App 10.0.12` + `Microsoft.AspNetCore.App 10.0.12`
- 本机 `C:\Program Files\dotnet\shared\` 最高只到 `10.0.10`，且缺 AspNetCore.App；无 .NET 10 SDK（只有 `%USERPROFILE%\.dotnet` 的 SDK 9.0.318）

虽然 .NET 通常能向下加载低版本 TFM 程序集（只要 API 存在），但未实测，且官方推荐插件 TFM 与宿主对齐。

### 风险 3（低但必须改）：A 阶段脚本路径失效
`a-script\config.json` 指向旧路径：
- `C:\Jellyfin\Data\data\jellyfin.db`
- `C:\Jellyfin\Data\metadata\People\`

若 Jellyfin 继续用新目录，这两个路径全部失效，回填任务会静默无效果。


## A 阶段脚本的遗留 Bug（建议修）

`a-script/localmeta.py` 第 318-319 行：
```python
q("SELECT COUNT(*) FROM BaseItemImageInfos WHERE ItemId=? AND ImageType=?",
  pid, IMG_TYPE_PRIMARY)          # ← pid 是 Peoples.Id
```
12.1.0 下头像记录挂在 `BaseItems.Id`（Person 条目）上，用 `Peoples.Id` 查会**全部查不到**，
导致脚本判定"所有人都没有头像"→ 重复回填。
修法：改成 `person.get(pid)`（BaseItems.Id），或兼容两个 Id 都查一遍。

其余配置无需改动：
- `config.json` 的 `personType` 已是 `MediaBrowser.Controller.Entities.Person` → 12.1.0 正好匹配
- `jellyfinDb` / `metadataDir` 仍指向 `C:\Jellyfin\Data\...` → 数据目录没变，路径有效
- `IMG_TYPE_PRIMARY = 0` → 与新格式一致

## 修复方案（原）

### 方案 A（推荐）：让 12.1.0 指回旧数据目录
- 做法：启动时加 `--datadir C:\Jellyfin\Data`，或设环境变量 `JELLYFIN_DATA_DIR=C:\Jellyfin\Data`
- 收益：媒体库、583 个演员目录、插件、A 脚本路径**全部不用动**
- 风险：10.11 → 12.1 跨大版本会自动迁移旧库（不可逆，必须先备份）；旧 plugins 里的 MetaTube / ThePornDB / TheTVDB 是 10.11 编译的插件，在 12.1 下可能加载失败，需要逐个验证

### 方案 B：留在新目录，重新部署
- 做法：把 LocalMeta 5 个托管 dll 复制到 `...\jellyfin\plugins\Jellyfin.Plugin.LocalMeta\`，改 A 脚本路径，重新扫描媒体库
- 收益：环境干净，无跨版本迁移风险
- 成本：媒体库要重扫，演员资料要重建（583 个目录的回填结果要从旧库重新导出或重跑）

### 方案 C：重编译为 net10.0（彻底解决 TFM 问题）
- 做法：装 .NET 10 SDK → csproj 改 `net10.0` → `Jellyfin.Controller` 升到 12.1.0 → 重新编译
- 收益：TFM 与宿主对齐，消除风险 2
- 成本：需要下载安装 .NET 10 SDK

### 建议组合
**先 A（保住现有数据），再 C（对齐 TFM），最后把 A 脚本路径按最终数据目录改一次。**

执行顺序：
1. 备份 `C:\Jellyfin\Data\data\jellyfin.db` 到 `jellyfin.db.bak_pre121_20261005`
2. 用 `--datadir C:\Jellyfin\Data` 启动 12.1.0，观察日志：迁移是否成功、LocalMeta 是否被加载、MetaTube/ThePornDB/TheTVDB 是否报错
3. 若步骤 2 成功 → 装 .NET 10 SDK → 重编译 net10.0 → 替换插件 dll
4. 若步骤 2 失败 → 回退到方案 B
