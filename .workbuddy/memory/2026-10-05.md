## Jellyfin 10.11.6 → 12.1.0 升级与适配

**背景**：本地 Jellyfin 从 10.11.6 升到 12.1.0，检查 LocalMeta 插件是否兼容。

**检查过程**
- 用 `tools/apiprobe` 对 12.1.0 程序集取证：插件用到的所有扩展点签名
  （`ILocalMetadataProvider<T>` / `IRemoteImageProvider` / `IScheduledTask` /
  `BasePlugin<T>` / `BasePluginConfiguration` / `RemoteImageInfo` / `ImageType` /
  `BaseItemKind`）与 10.11 **完全一致** → 代码层无需改动
- 首次排查误判：12.1.0 一开始用了新数据目录 `C:\Users\luckw\AppData\Local\jellyfin`
  （空库 548KB），插件目录里没有 LocalMeta。后来手动启动后它**自动接管了旧目录**
  `C:\Jellyfin\Data`，插件全部加载
- 关键教训：日志里 `Loaded plugin: "LocalMeta"` 那条对应的 `Jellyfin version` 是
  **10.11.6**，不是 12.1.0 —— 差点拿旧版本日志当兼容性证据

**迁移结果（全部继承）**
- 库路径 `\\HOMENAS\Porn Movie\番号` / `\\HOMENAS\Movie` 不变，Pron 库 2214 部不变
- 演员 1050 人，头像 726（69.1%，升级前 723=68.9%），简介 547（52.1%，升级前 353=33.7%）
- 用户 1 个 / UserData 1823 / ActivityLogs 5305 全部在
- 17:32 之后零 `[ERR]`，启动耗时 1:55

**B 插件结论**：net9.0 插件在 net10.0 宿主下**实测能加载**
（`Loaded plugin: "LocalMeta" "0.3.0.0"`）。不强求重定 net10.0 —— 重定还要装
.NET 10 SDK 才能验证，风险大于收益。文档里留了可选步骤。

## A 脚本适配（真实 bug，已修）

12.1.0 把 Person 的 `BaseItems.Id` 与 `Peoples.Id` 拆成两个 GUID，而头像记录挂
`BaseItems.Id`、`PeopleBaseItemMap.PeopleId` 指向 `Peoples.Id`。旧代码用 `Peoples.Id`
查头像 → 全部查不到 → 误判全员缺图 → 重复回填。

改动（`a-script/localmeta.py`）：
- 新增 `detect_person_type()`：自动探测 `BaseItems.Type` 写法，配置优先、查不到回退，
  10.11 / 12.1 通吃
- 头像判定优先用 `person_id`，退回 `peoples_id`
- 写入从"两个 Id 各写一条"改成只写 `person_id`（顺带修掉 10.11 下同值产生重复记录的旧缺陷）

验证（12.1.0 真实库，754 名 Actor）：待补头像 **754 → 27**，与升级前基线吻合；
待补简介 208。
